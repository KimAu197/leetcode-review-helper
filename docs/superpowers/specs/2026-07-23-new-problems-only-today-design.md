# 复习评分、刷题记录与新题进度分离：设计说明

## 目标

“今日刷题”和“已刷”页统计用户明确记录的实际刷题，包括新题和旧题重做；“新题进度”只统计首次刷题。完成复习评分时不增加刷题数量或出现在已刷日历中，同时保留“加入复习时同步记录刷题”设置。

## 数据行为

- 用户主动点击“记录刷题”，或开启同步设置后点击“加入复习”，继续通过 `logPractice()` 写入 `practiceLog`，记录类型为 `practice`，因此计入“今日刷题”和“已刷”。
- `logPractice()` 使用 `isNewProblem` 区分首次刷题和旧题重做；旧复习题手动记录时计入刷题总数，但不增加“新题进度”。
- 用户对已进入复习计划的题目完成复习评分时，只更新题目的复习历史、完成时间和下次复习日期，不向 `practiceLog` 写入 `review` 记录。
- `getTodayPractice()` 排除 `type === 'review'` 的记录，使当天已错误写入的复习记录立即不再显示或计入数量。
- `getAllPractice()` 排除 `type === 'review'` 的记录，使已有的自动复习记录不再出现在“已刷”日历、月度数量和日期详情中。
- 新题进度会兼容没有 `isNewProblem` 字段的旧数据：结合更早的刷题记录和题目加入复习库的日期推断是否首次刷题。
- 为兼容旧数据，没有 `type` 字段的历史刷题记录仍视为普通刷题记录。

## 修改范围

- `background.js`
  - 删除 `markProblemReviewed()` 中向 `practiceLog` 追加复习记录的代码。
  - 在 `getTodayPractice()` 的日期过滤基础上增加类型过滤。
  - 在 `getAllPractice()` 中增加类型过滤，统一保护“已刷”页面的数据源。
  - 在 `logPractice()` 中写入 `isNewProblem`，并让每日计划单独统计真正的新题。
- 不修改“加入复习时同步记录刷题”的设置、界面或 `addProblem()` 调用逻辑。
- 不删除或迁移用户现有数据。

## 验证

- 新题和明确记录的旧题重做都会出现在今日刷题与已刷中。
- 旧复习题点击“记录”不会增加“新题进度”。
- 当天刚加入复习计划的新题仍会增加“新题进度”。
- `type: 'review'` 的今日记录不会出现在今日刷题中。
- `type: 'review'` 的历史记录不会出现在“已刷”日历、月度统计或日期详情中。
- 没有 `type` 的旧记录仍会出现在今日刷题中。
- 完成复习评分后不会写入 `practiceLog`，但复习历史及下次复习计划正常更新。
- 开启“加入复习时同步记录刷题”后，新增题仍能写入 `practiceLog`。
